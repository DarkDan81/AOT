# Лабораторная 3. Классика против LLM

Из корня E:/AOT-work в общем окружении:

```powershell
python -m pytest lab03_classification/tests -q
python -m lab03_classification.run --classical-only
python -m lab03_classification.run --workers 2
python -m lab03_classification.timing
python -m lab03_classification.tokenizer_check
python -m lab03_classification.evaluate
```

До LLM-запуска должен работать локальный LM Studio. Код использует общий common.llm, одну модель Ministral 3 14B Reasoning, temperature=0, seed=42, JSON-schema с единственным label, max_tokens=64. Режимы zero_shot/few_shot отличаются только сохраненным промптом; few_shot содержит шесть примеров из train, по два каждого класса. API usage считает входные и выходные токены **родным токенизатором обслуживаемой Mistral-модели**, включая шаблон чата и системный промпт; деление числа символов на константу не применяется. tokenizer_check.py дополнительно использует lmstudio SDK 1.5.0 и метод tokenize уже загруженной модели для десяти train-текстов (модель не загружает и не меняет). Сырые token IDs, количество и время находятся в native_tokenizer.json. Эти счетчики не включают chat template, поэтому не заменяют API usage.

Файлы train/validation/test имеют 3000/500/500 строк и фиксированные SHA256 в data/provenance.json. Train/validation получены из исходных случайных постов, test — из исходного отдельного test; удалены классы speech/skip и дубликаты. Исходные метки не меняются. Pipeline TF–IDF(word ngrams1–2) + LogisticRegression выбирает только C из0.5/1/2 по validation macro F1. Другие гиперпараметры не подбираются. Baseline всегда возвращает наиболее частый train класс.

data/stress.csv содержит100 синтетических текстов: по20 отрицаний, опечаток, иронии, цитирования и смешанной оценки. Их создала **LLM OpenAI Codex непосредственно в рабочей сессии**, а не локальная оцениваемая Ministral. make_stress.py содержит исходный сгенерированный текст; stress_provenance.json раскрывает запрос, метод и критерии gold. SHA256 заморожен до оцениваемых запросов. Это не независимая человеческая разметка. Иронические сообщения в этой выборке отрицательные, поэтому распределения классов между категориями различаются. Код проверяет неизменность четырех наборов до запуска. Пересоздание stress после начала эксперимента запрещено без нового отдельного прогона.

Результаты каждого запроса сохраняются сразу в results/llm_responses.jsonl с usage, временем, параметрами, исходным JSON и признаком валидности; перезапуск пропускает уже полученные пары(id,mode). Автоматических retry и исправления JSON нет, невалидный ответ считается ошибкой классификации. --workers2 использует два одновременно выполняемых HTTP-запроса, поэтому измеренная задержка включает серверное планирование и не является временем эксклюзивного последовательного inference. Для последовательного независимого эксперимента нужен отдельный каталог результатов и --workers1. Классический метод измеряется по отдельным текстам.

results/predictions.csv объединяет все четыре режима; results/metrics.csv содержит accuracy, macro F1, среднее время, токены и стоимость1000 текстов. execution_runs.jsonl отдельно хранит wall time и throughput каждого запуска с учетом числа новых ответов. timing.py выполняет20дополнительных последовательных запросов по10train текстам; результаты не смешиваются с оценкой качества. evaluate.py вычисляет разрез по стресс-категориям и выбирает15реальных неповторяющихся примеров:5ошибок классики,5ошибок few-shot LLM,5расхождений; подробный разбор помещается в отчет. Для локальной модели внешнего тарифа API нет (0USD); электричество и амортизация не измерены. Кэш с исходными ответами не удаляйте: он служит доказательством реального выполнения и позволяет воспроизвести анализ.

Источник: [RuSentiment](https://github.com/text-machine-lab/rusentiment), доступная копия [strawberrypie/rusentiment](https://github.com/strawberrypie/rusentiment). Конкретные URL и хеши сохранены в data/provenance.json. Стресс-тексты — новый синтетический материал данной работы.
