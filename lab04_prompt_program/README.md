# Лабораторная 4. Промпт как программа

Авторы: Дущенко Даниил Александрович и Коваленко Евгений Юрьевич, группа К3341.

Из корня репозитория, в общем Python-окружении:

```powershell
python -m pytest lab04_prompt_program/tests -q
python -m lab04_prompt_program.run
python -m lab04_prompt_program.evaluate
python -m lab04_prompt_program.behavioral
python -m lab04_prompt_program.sensitivity
```

Последняя команда пересчитывает чувствительность F1 к трём исправлениям gold после независимой проверки. Первоначальный эталон и основные результаты сохранены; `data/gold_review_audit.md` описывает исправления, а `results/sensitivity.csv` показывает обе оценки. Новые запросы к LLM для этого анализа не нужны.

Зависимости: pydantic >= 2, pytest и зависимости общего common.llm. LM Studio должен обслуживать модель, указанную в общем интерфейсе. Runner дописывает результаты по одному отзыву/версии и пропускает уже сохраненные пары. Для полного нового прогона сохраните прежний файл results/predictions.jsonl под другим именем.

В data/reviews.jsonl находятся 50 **полных отзывов**, восстановленных группировкой по file_name и sentence_id. Правило отбора — 50 самых коротких из 500, сортировка по длине и ID; это экономичная, но смещенная к коротким отзывам выборка. Gold содержит исходные аннотации Drugname/DI/ADR и адаптацию к полям задания, включая positive_effect; он не является независимой экспертной медицинской разметкой. Все изменения явно перечислены в prepare.py. SHA256 фиксирует gold до запуска. prepare.py запускают только при осознанной пересборке эталона.

Два промпта сохранены в prompts. Обе версии используют одинаковое ограничение JSON-schema при декодировании, temperature=0, seed=42, max_tokens=2048 и лимит ровно одной повторной попытки при невалидном ответе; version_2 дополнительно проверяет покрытие извлечений цитатами. Поэтому JSON-валидность оценивает систему с constrained decoding и не изолирует влияние промпта на свободную генерацию. Сохраняются исходные ответы, ошибки проверки, повторы, токены и время. Ошибки транспорта не заменяются выдуманными ответами. JSON parser строгий, Markdown не удаляется. Метрика качества — micro F1 уникальных пар (поле, словесный токен); она не требует одинаковых границ фразы, но не проверяет медицинскую причинность. Неподтвержденное извлечение в автоматическом счетчике — строка, отсутствующая в тексте; семантически неверное извлечение с настоящей цитатой разбирается отдельно.

Unit-тесты используют явно обозначенный fake backend и проверяют контракт/повторы. Принятие подготовленного корректного ответа тестом не доказывает, что настоящая LLM правильно обрабатывает отрицания: ее качество оценивается отдельным сохраненным прогоном.
